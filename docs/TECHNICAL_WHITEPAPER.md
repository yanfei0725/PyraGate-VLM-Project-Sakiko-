# 第 0 章 路线定案：自研底座

## 0.1 路线变更说明

项目早期曾基于社区蒸馏权重（Hummingbird-XT）采用零训练外挂路线。经系统性实测评估，该路线的上限不足以支撑项目目标，已切换为自研底座 + 蒸馏训练路线。本版文档自此节点起；早期路线的详细实验过程不在本文档范围内。

## 0.2 新底座定义（一句话 + 详细）

> **Udit 4.5B DiT 主干（即自研 4.5B 3D U-ViT）**：以**双轴混血（M85 权重 + 时序低通算子）**为蒸馏教师（实测 flicker 0.0244 / 身份 0.9892）、20 步对齐训练、流匹配速度场为蒸馏目标的自研学生；对称 U 型 + 长 skip 骨架，AdaLN-Zero 条件注入，2+1D 时空注意力分解（GSA，含 3D RoPE），SwiGLU 前馈，输出头带时序辅助分支；最高分辨率 decoder 末端挂载 3×500M 通用增强专家（多风格覆盖：二次元/写实/3D）；16GB 单卡上以混合 INT8 + 分时加载部署。图中「冻结」指**推理期冻结**；训练期主干照训，本轮只训主干、三专家冻结。

# 第 1 章 项目概述与定位（训练线版）

## 1.1 背景与痛点（继承 v1.2 §1.1）

人设漂移、风格漂移、时序崩坏、色彩频闪、部署门槛五大痛点不变。新增一条由换底座带来的痛点：**通用视频底座在画质/时序/可控性上结构受限**——2D DiT + 外挂条件的设计，使时序稳定性与风格可控性都只能靠推理侧补救，补救空间已被 v1.2 实测触及天花板。换底座的目标不是服务某一题材，而是全方位抬高画质、速度与能力的上限。

## 1.2 核心定位（改写）

> Sakiko v2：面向通用场景的全方位全能型本地单卡视频生成系统——**更高画质、更快采样、更强能力**，覆盖写实/二次元/3D 等多风格题材，不绑定任何特定场景。**底座为自研 Udit 4.5B DiT（3D U-ViT），以双轴混血（M85 权重 + 时序低通算子）为教师、20 步对齐蒸馏获得基础能力，以 3×500M 通用增强专家（本轮冻结）实现多风格与画质增强，以混合量化 + 分时加载 + AsT/TrEE 调度实现 16GB 单卡上的高性价比部署**。自研核心 = 主干架构 + 蒸馏链路 + 专家体系 + 调度管线 + 校验规则。

与 v1.2 的本质区别：v1.2 是「拿别人的权重做零训练增强」，v2.0 是「自己训一个面向通用全能目标的底座」。前者工程风险低但上限被底座锁死，后者需要训练资源但上限由自己定义。v2.0 接受这个取舍，换取的是画质、速度、能力三个维度同时向上的空间。

## 1.3 设计原则与红线（继承 + 改写）

架构原则四条保留（双核解耦 / 外挂可插拔 / 契约先行 / 单向数据流）。工程原则调整：

- **「主干冻结优先 / 零训练优先」在 v2.0 中降级**：底座本身需训练，冻结原则仅适用于「训练收敛后的部署期」与「协核权重」；
- **新增「分层可消融」原则**：每个结构改动（AdaLN、skip 门控、2+1D、专家）必须可单独关闭并回退到对照形态，否则无法定位收益来源。
- **本轮训练范围（V2-22 最终定案）**：**可训练 = 主干（Udit 4.5B DiT：GSA + Dual-Act SwiGLU，无额外 FFN）+ 北大桥投影 MLP / 风格小头**；**冻结 = Qwen3-VL 1B 基座 + MoE 三专家（本轮不用）+ 感知栈/cond_mod 投影/推理组件**。严守单向数据流（VLM 仅前向产条件、梯度不回传、latent 不回流）。三阶段推进：阶段1 主干+投影头 → 阶段2 冻主干训专家 → 阶段3 冻主干与专家、只微调 VLM 侧（基座恒冻）。此条取代 V2-21 的"VLM 全冻结 / 只训主干"旧口径。

红线（继承 v1.2 七条 + 新增两条）：

8. **【红线】可学习 skip 门控必须可置 0 退化**：置 0 后须与无 skip 直筒 DiT 逐 bit 对齐（延续 gate=0 逐 bit 回归纪律）；
9. **【红线】敏感层不得量化**：时序注意力、skip 门控、AdaLN 调制头、输出预测头、瓶颈层强制 fp16/bf16——这是画质与时序稳定性的底线（见 §7.2）。

**全方位目标（本版定位校准）**：v2.0 不以任何单一题材（如 ACG 插画）为设计边界，目标是通用场景下的「更高画质、更快采样、更强能力」——

- **更高**：2+1D 时序原生 + 加权 skip + 通用增强专家 + 评测四组对照，以画质与稳定性指标为准绳；
- **更快**：混合量化（§7）+ 分时加载 + VLM 前置卸载 + AsT/TrEE 调度（§2B.7），把单卡时延压到可用区间；20 步对齐教师后不再依赖压低步数（§2.5）；
- **更强**：多风格/多主体/长视频/推理增强套件的全分支可消融集成（§9/§12），覆盖面与上限同时打开。


## 2.5 采样步数（范式改变）

v1.2 的「3 步固定」是 XT 蒸馏学生的硬约束。**v2.0 学生由我们自己的蒸馏链路定义**，步数不再是外部给定，而是蒸馏目标的一部分。

**V2-21 定案：教师 20 步、学生跟 20 步训练**。原「3~4 步少步路线」不再是默认设定，已被 20 步对齐训练取代：

- **教师步数 = 20 步**：双轴混血（M85 权重 + 时序低通算子）以 20 步采样产出蒸馏目标；
- **学生步数 = 20 步**：主干训练全程跟 20 步对齐，σ 表与调度在 20 步上标定，不沿用 v1.2 的 3/4 步校准表；
- 【工程推断】「更快」目标改由混合量化（§7）+ 分时加载 + VLM 前置卸载 + AsT/TrEE 调度实现，不再依赖压低采样步数；若后续要探少步，须以 20 步基线为起点重新蒸馏并单独消融，不得直接套旧表；
- 分阶段条件强度调度（继承 v1.2 §8.5）在新底座的 20 步上重新消融，不直接继承旧边界；
- 动态 sigma / 步数路由类机制（v1.2 分支 B-DynSigma）复入条件改为：20 步基线稳定且校准表覆盖足够宽时。

# 第 2B 章 推理主线架构（最新架构完整总述，V2-21）

> **本章性质**：按提供的「PyraGate-VLM / Project Sakiko 架构完整文字总述」落文，是架构的**权威描述**。此前架构图中的标签（Higuro / Act_T / TriFE 等）按定案原样保留作对照，但以本次文字总述的校准术语为准（**Hipfire 引擎 / AsT 事件调度 / TrEE 资源树**）。**旧白皮书写死约束全部丢弃，仅保留有效技术参考**；与本章冲突处一律以本章为准。
>
> **「冻结」的统一解释**：图中主干「Udit 4.5B DiT｜冻结」指**推理期冻结**（部署态权重固定），训练期主干照训（§8.3 本轮只训主干）；协核 Qwen3-VL 1B 则是「推理强制挂载、权重冻结」。两者不矛盾。
>
> **基准**：Udit 4.5B 主干 + Qwen3-VL 1B 协核，协核运行在 Hipfire 引擎上；MoE 三专家一一对应：二次元专家 / 写实专家 / 3D 专家；协核三风格小头同样为二次元头 / 写实头 / 3D 渲染头。

## 2B.0 主线十段速览

1. **承载**：1B 协核 Qwen3-VL 运行于 Hipfire，强制挂载、推理冻结；三层感知栈输出给三组风格小头（二次元/写实/3D）。
2. **跨核通信**：cond_mod ≈2KB/窗口，主线为窄通道摘要代理、事件驱动（慢漂移保护）、CoW 零拷贝、自适应降级、单向数据流红线；差分/影子 KV/熵编码打包为判例分支，保留设计，满足载荷升级条件才启用。
3. **北大桥**：协核输出条件向量注入主干，两条路径——瓶颈 Block 走 AdaLN 调制、浅层 Block 走 CrossAttn KV。
4. **主干 Udit 4.5B DiT**：GSA 时空注意力 + Dual-Act 分段 SwiGLU；MoE 三专家和协核风格头一一对应，由风格信号动态路由激活；Dual-Act 分段阈值 t 由 VLM Slot 特征控制。
5. **X3D 缓存**：浅层 Skip 热缓存、相似度淘汰；持久 KV 严格限定在流式冻结条件帧（Frame Sink），远期 KV 做 FP8 换页。
6. **补丁**：画质补丁、流体 NS 散度涡量约束补丁，均为推理侧零训练外挂，可开关；流体区域按 mask 做路由分流。
7. **OPS 校验**：协核兼任校验器，时序轨迹打分分级处置，支持回退重采样；增补 Claude OPS 语义断言模块。
8. **调度**：AsT 事件调度 + TrEE 资源树，托管显存快照、CoW 缓冲、降级兜底。
9. **输出**：Frame-Sink 滑窗输出 → 球形金字塔多尺度并行 → TurboVAE 解码链路。
10. **基线对照**：原生 XT、gate=0（关闭 VLM 调制，Dual-Act 保留）；V2 训练分支离线独立，不侵入 V1 推理流。

## 2B.1 协核侧（Hipfire Runtime）

Hipfire 承载 Qwen3-VL 1B W4A8 协核，推理强制挂载、权重冻结，负责 KV 分页、W4A8 量化算子调度、显存换页。

协核内置三层感知栈：Qwen 语义编码 + SAM2 掩码传播 + ReID/IoU 实例匹配。

感知栈输出流向三处：

1. **三组独立 Alpha 权重的风格小头**：二次元头 / 写实头 / 3D 渲染头，输出风格特征向量；
2. **cond_mod 窄通道摘要代理**：payload 划分 identity / style / color / motion / fluid，附带版本号，过期直接丢弃；单窗口载荷固定约 2KB；
3. **时序校验子系统**：两套并行校验逻辑——原生 OPS 轨迹校验 + Claude OPS 断言校验。

### Claude OPS 断言（新增模块）

定位：高阶语义断言校验层，和原生光流 OPS 并行，**不是替换关系**。

- 输入：协核感知特征、当前窗口 prompt 语义、实例 slot 注册表、上一帧全局语义上下文；
- 断言集合（运行时动态编译）：角色身份断言、物体属性断言、空间关系断言、动作时序断言、画风一致性断言、镜头约束断言；
- 工作模式：非逐像素打分，做语义谓词判定；支持软断言（警告、权重衰减弱化约束）、硬断言（触发回退重采样）；
- 和原生 OPS 分工：
  - 原生 OPS：低阶信号，光流、像素相似度、身份特征向量匹配，抓形变、闪烁、画面崩坏；
  - Claude OPS 断言：高阶语义，抓逻辑崩坏——人物肢体矛盾、物体属性错乱、动作时序冲突、画风与选定风格头不匹配；
- 处置链路：断言失败分级。软失败：给 Denoise 施加约束偏移，不回退；硬断言不满足：上报 AsT 调度，触发窗口回退，复用前序稳定条件 KV 重走采样；
- 开销：断言推理复用 Hipfire 上的 VLM 前向，不额外拉起独立模型；断言规则集热加载，推理时可开关该整套模块。

## 2B.2 跨核通信体系（主线 + 判例分支）

通信核心三目标：切断协核—主干紧耦合、压低跨核传输量、按需触发传输。量级结论：**2KB/窗载荷本身不构成带宽瓶颈**，通信收益核心是节省协核重复前向（数百 ms/窗口）+ CoW 零拷贝，不是压缩字节。

**主线落地项**：

1. 窄通道摘要代理（地基契约）；
2. 事件驱动通信 + 慢漂移保护：突变触发更新，同时设固定 K 窗口强制刷新，规避检测器捕捉不到的缓慢时序偏移；
3. TrEE 托管共享 CoW 零拷贝缓冲；
4. 自适应降级代理：BF16 → FP8 压缩 → 极简身份向量，负载压力回落自动恢复；
5. 单向数据流红线：latent、主干 KV 禁止回流协核，仅协核向主干下发条件信号。

**判例分支（代码保留、默认不启用，满足复入条件才评估开启）**：

- B-Diff 增量差分传输：复入条件——per-token 条件图启用、多层特征路由开启，单窗口载荷升至 MB 级；
- B-ShadowKV 影子 KV 索引：复入条件——后续改版采用协核—主干紧耦合交叉注意力架构；
- B-Quant 熵编码打包：复入条件同 B-Diff；当前跨核 cond_mod 裸传 BF16。

## 2B.3 北大桥（条件对齐旁路）

协核 cond_mod 向量经北大桥投影对齐，双注入路由：

- **DiT 瓶颈 Block**：AdaLN 条件调制；
- **DiT 浅层 Block**：per-token CrossAttn KV 注入。

桥接自带独立 gate 开关：gate=0 时关闭全部 VLM 条件注入，Dual-Act 模块本身保留，作为**阴性对照基线**。

## 2B.4 Udit 4.5B DiT 主干

主干推理冻结。基础链路：GSA 时空路由注意力（3D RoPE）→ Dual-Act SwiGLU → MoE 三专家。

- **Dual-Act SwiGLU**：分段激活，`|z| < t` 使用 SiLU，`|z| ≥ t` 平滑压缩；逐 token 阈值 `t` 由 VLM Slot 特征经北大桥下发控制；
- **MoE 三专家**：二次元专家 / 写实专家 / 3D 专家；路由信号来自协核风格小头输出，与风格头一一绑定，按需激活；**不存在常驻通用专家**；
- **本轮训练状态（项目定案）**：只训主干，三专家冻结不训练、门控固定；教师 = 双轴混血（M85 权重 + 时序低通算子），20 步，flicker 0.0244 / 身份 0.9892。

## 2B.5 X3D 分层缓存 & KV 语义规则

**KV 语义重写**：扩散无跨步自注意力 KV；持久 KV 只允许在流式生成范式下开启「冻结条件帧 KV」，等价 XTX Frame Sink。

**X3D 分层缓存**：

- 浅层热缓存：Skip 特征就近融合，基于帧相似度判定复用/淘汰；
- 深层残差特征：高动态区域强制重算，不驻留；
- KV 分级存储：近期 KV 高精度保留，远期 KV 老化转 FP8 换页到 Host。

## 2B.6 外挂补丁组（零训练，推理侧可独立开关）

1. **画质补丁组**：运动掩码差异化注意力、色彩亮度锚 + 值域钳位、感知时序衰减融合、亚像素抖动抑制、分阶段约束 + 动态 sigma、参考特征衰减池、镜头元感知路由；
2. **物理流体补丁**：Taichi 轻量速度场、NS 散度 + 涡量约束；按实例 mask 路由——人物区域关闭流体约束、刚体施加急动度约束、流体区域启用场引导。

补丁约束信号全部由协核感知栈生成，注入 GSA / Denoise 环节。

## 2B.7 AsT 调度层 + TrEE 资源树管理器

- **AsT**：事件优先级队列、乒乓双缓冲、预通知预热、静态依赖预解析、松弛分层校验、前瞻 N+1 预调度、异步失败兜底旁路；
- **TrEE**：全局显存池、条件资源只读快照、CoW 缓冲页锁保护，防止关键条件张量被换页逐出 HBM；
- 所有校验失败（原生 OPS + Claude OPS 断言）的回退、降级、重采样动作全部交由 AsT 统一调度。

## 2B.8 输出链路

Denoise 输出 → Frame-Sink 滑窗 → 球形金字塔多尺度并行分层 → TurboVAE 解码 → 时序色彩稳定器 → ReActor 身份兜底对齐 → 最终视频帧序列。

## 2B.9 评测闭环

指标：身份相似度、PSNR、SSIM、LPIPS、闪烁度；额外接缝专项评测。固定双基线：**原生 XT 基线**、**gate=0 关闭 VLM 调制基线**（Dual-Act 保留）。教师锚点 flicker 0.0244 / 身份 0.9892。

## 2B.10 V2 离线训练分支

完全独立于 V1 推理主线，离线使用。可训练参数：VLM 投影头、三组风格小头、LoRA 身份锚点库；训练目标对齐 MoE 专家分布和 Claude OPS 断言语义约束。**不侵入 V1 推理流**。

## 2B.11 完整校验链路汇总

两条校验并行，统一上报 AsT：

1. **原生 OPS**：光流 + 特征向量相似度 → 抓画面形变、闪烁、像素级漂移；
2. **Claude OPS 语义断言**：角色/物体/空间/动作/画风谓词判定 → 抓语义逻辑崩坏。

分级处置逻辑共用：正常 → 写入 KV 缓存；轻微异常 → 权重衰减弱化；硬违规 → AsT 触发窗口回退重采样。

# 第 3 章 生成主干：3D U-ViT 分层改进（V1 基线）

## 3.1 原版 U-ViT 的四大原生短板（调研确认）

1. 【已核实】原版面向 2D 图像，直接扩 3D 注意力易时序震荡、闪烁；
2. 【已核实】条件注入用 token 拼接（t token + 文本 token 与图像 patch 一起 self-attn），与视频扩散主流调制范式差异大；
3. 【已核实】单分辨率，全局注意力开销随 token 数平方增长，缺多尺度语义分离；
4. 【已核实】长 skip 直接相加无权重约束，浅层噪声沿 skip 污染深层（Skip-DiT，arXiv 2411.17616 专门分析此问题）。

## 3.2 条件注入：token 拼接 → AdaLN-Zero【基底材料】

- 移除独立时间 token、文本 token；
- 每个 Block 使用 AdaLN-Zero，输入时间步 emb + 文本 emb 调制；
- 初始化 γ≈1、β≈0、gate α≈0，Block 初始近似恒等映射，梯度稳定（DiT 原论文；TPAMI 2026 有专门机制研究）；
- **真实动机**（纠正 v1.2 叙事）：利于训练稳定 + 后续扩展多路 VLM 特征调制，**不是**为了贴近 Wan（见 §3.8）；
- 代价：不再严格 1:1 复刻 U-ViT 论文。

## 3.3 Skip：加权门控 + 谱约束【基底材料，α 初值为工程推断】

```
x_deep = x_deep + α_skip · Norm(skip_feat)
```

- α_skip 每个对称层单独学习，初始值取 0.1【工程推断，非 Skip-DiT 论文原始结论】；
- 对 skip 特征做谱约束，抑制高频噪声沿 skip 传递（Skip-DiT 谱分析精神）；
- 【红线】门控可置 0 退化为直筒 DiT 做对照消融（§1.3 红线 8）。

## 3.4 时空注意力：2+1D 分解【基底材料】

- 空间头：单帧构图/纹理；时序头：帧间运动/连续性；
- 时序头加因果掩码（长序列抑制跨帧乱跳；视频流匹配非强制因果）；
- 瓶颈层保留完整 3D 联合注意力，学全局运动——**同时更接近教师 Wan 的 Full Attention 范式**（§3.8）。

### 3.4.1 GSA 门控混合时空注意力【设计选定，另一条成熟路线】

设计选定增加 **GSA（Gated Spatial Attention）**，作为 2+1D 交替之外的并列路线：

- 空间头与时序头**并行**计算，用可学习门控逐 token 混合：`y = g·y_s + (1-g)·y_t`，门控由条件向量投影 + sigmoid 得到；
- 输出门零初始化，初始近似恒等（延续 AdaLN-Zero 的稳定性哲学）；
- 与 2+1D 交替的关系：两条路线都用同一个 `attn_strategy` 开关切换（`alternate` vs `gsa`），**A/B 对照验证后再定主线**，不预设 GSA 更优；
- 骨架已实现（`model/uvit3d.py:GSA`），CPU 自检通过；门控源当前用 `cond`，可换 per-token 特征，属【工程推断】待消融。

### 3.4.2 位置编码与注意力后端【设计选定补充】

**3D RoPE（已落地）**：对齐教师 Wan2.2 的 `rope_params`/`rope_apply`——按 head_dim 生成复数频率，再按 t/h/w 三组分频（c-2⌊c/3⌋, ⌊c/3⌋, ⌊c/3⌋）对每个 (f,h,w) 网格施加。学生按注意力域分别取 grid：空间头 (1,H,W)、时序头 (T,1,1)、瓶颈 Joint (T,H,W)。CPU 自检逐值对齐教师手工复算，且保范数、位置敏感。

**FlashAttention-2 后端（定案，已落地适配层）**：

- 配置 `UViT3DConfig.attn_backend` 默认 `"flash2"`（可选 `auto`/`sdpa`/`math`），贯通 encoder / bottleneck / decoder 所有 SelfAttention，含 GSA 的两个子注意力；
- 解析优先级：`flash_attn` 包（真 FA2 kernel）→ torch SDPA `FLASH_ATTENTION` backend → 普通 SDPA → math；
- **诚实边界**：真 FA2 kernel 仅 CUDA/ROCm + fp16/bf16。CPU 或 fp32 时明确降级 math 并在日志标注，**不把 math 冒充 FA2**；本轮全程纯 CPU，只做数值对齐与后端选择自检；
- 本机环境实测（2026-11-21）：`flash_attn` / `flash_attn_interface` 均未安装；torch 2.9.1+rocm7.2.1 的 `flash_sdp_enabled=True`、`sdpa_kernel` API 可用。因此上显卡 + bf16 时会走 SDPA FLASH 路径；若要真 FA2 kernel 需另装 `flash_attn` 包（【待 GPU 验证】）；
- 自检：`flash2`/`auto`/`sdpa`/`math` 四链路输出与手写参考注意力逐值一致，causal 掩码正确。

## 3.5 前馈：SwiGLU【基底材料】

- 替换普通 GELU MLP；SwiGLU = Swish(a) ⊗ σ(b)，LLaMA/PaLM 标配；
- **设计选定：`mlp_ratio=8/3`，参数持平原生 FFN**。校验：原生 `d→4d→d` = 2 个矩阵 = `8d²`；SwiGLU `d→(8/3)d→d` = 3 个矩阵 = `8d²`。已在骨架中实测（tiny：32,832 ≈ 32,768）。
- 【工程推断】"视频流匹配收敛更快"缺该场景直接证据，按消融验证。

## 3.6 输出头：时序辅助分支【工程推断】

- 主体输出速度场（流匹配）；
- 轻量时序辅助头输出帧间相似度残差，训练期加 flicker 正则 loss，提前约束 skip 带来的帧间抖动；
- 【风险】辅助头过强会压制正常运动（把该动的画面抹平），权重需小心标定；
- 【未核实】该具体设计未找到直接先例，属工程创新，按 §12 消融验证。

## 3.7 蒸馏对齐（本版最高 ROI 项）

1. **主 loss**：教师速度场 MSE（流匹配，Lipman 2023 / Rectified Flow 范式）——教师 = 双轴混血（M85 权重 + 时序低通算子），20 步产出目标；
2. **辅助 loss（加权）**：
   - 帧间时序一致性 loss（抑制闪烁；参考 DiffSynth TCR 的 Lipschitz 约束思路），对标教师 flicker 0.0244；
   - **层特征对齐 loss**：学生各层隐特征与教师对应层对齐，不只对输出对齐——REPA / U-REPA / VideoREPA（NeurIPS 2025）证明这是加速迁移的最强杠杆；Wan DiT 仅作架构参考层位映射，不作教师；
3. **课程蒸馏**：先 33f 短帧，再升 121f 长帧，全程跟 20 步；
4. **α_skip 课程**：前期锁小（先学基础流匹配），后期放开（学细节）；本轮只更新主干参数。

## 3.8 关键纠错：与 Wan 教师的架构对齐度（本次调研核心发现）

基底材料的原始逻辑是「改 AdaLN 是为了贴近 Wan 的调制范式，降低蒸馏对齐难度」。调研核查后此前提不成立：

| 维度 | 教师 Wan 2.1 | V1 学生 | 差异变化 |
|---|---|---|---|
| 文本条件 | cross-attention（T5） | AdaLN 调制 | **变大** |
| 注意力 | Full Spatiotemporal Attention | 2+1D 分解 | **变大** |
| 时间步 | AdaLN | AdaLN-Zero | 变小 |
| 框架 | Flow Matching | Flow Matching | 一致 |

**结论**：改动后学生在文本条件通路和注意力结构上与教师更不同，而非更接近。因此——
- 架构改动的价值在于**小模型的训练稳定、时序稳定、计算效率**，不在于贴近教师；
- **弥合教师-学生差异的正解是 §3.7 的层特征对齐 loss**，它不要求架构同构；
- 本版据此把层蒸馏从"辅助项"提升为 V1 必做项（V2-6 修订）。

## 3.9 主干红线

继承 v1.2 §3.6 五条 + 本版新增：门控/残差/归一改动必须可消融回退；敏感层不得量化（§1.3 红线 9）；蒸馏必须先于专家训练收敛（§5.3）。

# 第 4 章 金字塔分层 U-ViT（V2 进阶）

## 4.1 硬约束：V2 不得一步到位

**【红线】先用 V1 单分辨率版本跑通基线，确认时序稳定性可控，再迭代金字塔。** 这是基底材料明确要求，本版升格为红线。

## 4.2 时空 Patch Merge / Unpatch【基底材料】

- 支持 (T,H,W) 三维 merge，可单独控制时间维度降采样倍率；
- 推荐空间每 stage 缩 2 倍、时间保持不变，避免运动模糊；
- 【避坑】不要同时压缩时间+空间（运动信息易丢）。

## 4.3 多尺度条件路由【基底材料】

- 低分辨率瓶颈 stage：接收粗语义（文本全局 emb、VLM CLIP 全局特征），管大构图/主体运动轨迹；
- 高分辨率 stage：接收 VLM 细粒度特征、参考图身份特征，管材质/笔触/细节；
- **增强专家只挂最高分辨率 decoder 末端**——粗阶段不介入风格/画质修正，防止打乱运动布局【避坑清单】。

## 4.4 跨尺度时序对齐 loss【工程推断】

不同分辨率预测的速度场之间加一致性 loss：低分辨率运动流上采样后与高分辨率对齐，解决金字塔常见的"运动错位"。未找到成熟直接先例，按 §12 消融验证。

3. 联合微调门控 —— **本轮冻结不执行，延后**。

避免专家抢占基础任务。**V2-21 定案**：本轮只训主干，三个 500M 专家权重冻结、门控固定；步骤 2/3 待主干在教师（flicker 0.0244 / 身份 0.9892）对标下达标后再单独排期。注意本节的「冻结专家」与图中主干「冻结」标注不同——后者指推理期冻结，训练期主干照训。

### 6.6.1 北大桥（连接器，预训练权重可直接复用）

本地参考：`backups/baseline_v1_20261121/custom_nodes_ComfyUI-WanVLMBridge/wan_vlm_bridge.py`（逐行对齐 LoomVideo `loomvideo.py:30-58`）：

```
Qwen3-VL hidden [B,L,4096]
  -> QwenRMSNorm(输入端, fp32 累加后乘 weight)
  -> Linear(4096, 4*3072=12288) -> GELU(tanh)
  -> Linear(12288, 3072)   => 主干条件空间 [B,L,3072]
```

- **权重可 strict 加载**：`gen_model.pth` 里 `mllm_embedder.*` 5 个张量（norm.weight / linear_1.w+b / linear_2.w+b），88M 参数（bf16 ≈84MB，fp32 168MB）；mmap 只触碰这 5 个张量页，不搬动 9.7GB 全量；
- 已逐值自检：桥前向 == 手工参考实现（防"自己验自己"）；
- **这修正了 v1.2 §6.4 的"必须训练连接器"表述**：北大桥提供了**预训练起点**，v2.0 的训练是"在此起点上微调/对齐"，而非从零训练。

### 6.6.2 多尺度分层注入（白皮书 §4.3 落地）

| stage | 注入方式 | 语义职责 |
|---|---|---|
| 低分辨率（encoder 前段，前 `stage_ratio` 的 block） | 桥输出**全局池化** → 并入 AdaLN cond | 粗语义：大构图/主体运动 |
| 高分辨率（decoder 后段） | 桥输出 **per-token** → CrossAttn KV（`Q=U-ViT token, K/V=VLM`） | 细粒度：材质/笔触/身份 |

- 桥每步只算一次，全局与 per-token 两路径复用；
- CrossAttn 输出门**零初始化 → 初始逐值恒等**（继承 v1.2 ref=0 红线，自检验证）；开门后注入生效；
- 不传 VLM hidden 时自动退化为无 VLM（向后兼容）；
- 实现：`model/vlm_bridge.py`（`NorthBridge` / `CrossAttnInjector` / `VLMInjector`），接入 `model/uvit3d.py:UViT3D.forward(vlm_hidden=...)`。

### 6.6.3 避坑（继承 v1.2 钩子经验）

- 门控 ref=0 必须逐 bit 恒等（含 NaN guard，0×inf 是真实 bug 类）；
- 协核输出回 fp16 进主干，误差隔离；
- per-token 条件与窄通道契约存在带宽张力——cond_mod 从 2KB/窗升级，通信章分支 B-Diff/B-Quant 的复入条件（载荷进 MB 级）**可能重新触发**，挂【待核验】；
- 【工程推断】stage_ratio 当前默认 0.5，分界点需消融；门控形式、归一化位置按实验微调。

# 第 7 章 16G 显存与混合量化部署（本版核心工程章）

## 7.1 权重账（基底材料数据，注意口径）

| 组件 | bf16 | int8 |
|---|---|---|
| 4.5B U-ViT | 9 GB | 4.5 GB |
| 单 500M 专家 | 1 GB | 0.5 GB |
| 轻量 VAE | 0.3~0.6 GB | 不量化（保 fp16） |
| VLM | 不常驻 | 不计入 |

无脑全 int8 = 5GB 看似宽裕，但**量化损失是最大风险**——故采用混合量化（§7.2），权重略大于 5GB 但画质/时序损失可控。

## 7.2 混合量化分层清单（红线层表）

| 层 | 精度 | 理由 |
|---|---|---|
| 主干 FFN（SwiGLU）、普通自注意力权重 | **int8** | 收益大、鲁棒性高，最适合量化 |
| 时序注意力 | **fp16/bf16** | 一量化加重闪烁、运动漂移 |
| skip 融合、门控 α | **fp16/bf16** | 量化扰动 skip 权重→高频噪点 |
| AdaLN-Zero 调制层/头 | **fp16/bf16** | 调制误差直接进特征分布 |
| 输出预测速度场 Head | **fp16（强烈建议）** | 输出头误差直接污染 ODE 速度场 |
| 瓶颈层 | **fp16/bf16** | 3D 联合注意力，全局运动关键信息 |
| VAE | **fp16** | 轻量，不值得量化 |
| KV cache | **int8（独立选项）** | 时序 KV 减半，对视频时序影响很小，性价比极高 |

**【红线】** 这张表是画质与时序稳定性的底线，不得为省显存突破。若 16G 仍紧，走 §7.6 预案，不动这张表。

**int8 档位**（继承 v1.2 实测）：W8A16 per-channel，激活 bf16；量化一律走 AMD Quark 官方管线，禁手搓。

## 7.3 激活 / KV / skip 节流（权重之外的真正大头）

基底材料关键洞察：**权重压到 int8 只是第一步，激活张量、时序 KV、skip 特征池默认仍 fp16，这块才是 16G 卡的杀手。**

| 手段 | 做法 | 收益 |
|---|---|---|
| KV int8 | 开启 int8 KV cache（与权重量化独立） | 时序 KV 减半 |
| skip 冷热分级 | 高分辨率/高开销 skip：融合即丢弃不缓存；低分辨率瓶颈 skip：选择性缓存 | 砍掉最大中间特征池 |
| 梯度关闭 | 推理全程 inference_mode，不保留任何反向图 | 继承 v1.2 工程卫生包 |
| 缓冲区复用 | ODE 采样器临时缓冲区 in-place tensor，尽量复用不新建 | 降碎片峰值 |
| 专家按需单加载 | 一次只加载一个 500M 专家 | 省 0.5~1GB |

## 7.4 分时加载时序表（16G 最终常驻规划）

| 阶段 | 常驻内容 | 显存 |
|---|---|---|
| 阶段1 初始化 | VLM（提取完即卸载） | 临时 ~6.31GB |
| 阶段2 采样（峰值） | 混合量化 4.5B U-ViT ≈5.5GB（含少量 fp16 敏感层）+ 单 int8 专家 0.5GB + latent/int8 KV/少量缓存 skip ≈6~7GB | **合计 12~14GB** |
| 阶段3 解码 | 卸载主干+专家后加载 VAE | 独立峰值，不叠加 |

**余量**：12~14GB 峰值，给系统驱动/CUDA 上下文/临时张量留 2GB，卡在 16G 安全区间。

## 7.5 VAE 分块解码（tiled decode，收尾安全阀）

**边界声明**：tiled decode 只管 VAE 解码阶段，**不解决 U-ViT 采样主循环的显存压力**，是收尾环节的保险（基底材料明确；v1.2 已有 TurboVAED 14×/4×，本版在其上叠加帧对齐分块）。

分块逻辑：整张 latent 切重叠 tile，逐块解码、算完释放中间特征，最后拼接融合消接缝。

**视频场景四个坑（与图像 tiled 不同）**：

1. **不要单帧独立切 2D tile**——帧间 tile 边缘会闪烁、接缝抖动；改用 3D 时空 tile（带时间窗口），或最低保底：固定 tile 网格坐标，全视频所有帧切块位置完全一致 + 融合权重跨帧平滑；
2. **只开 tiled decode，编码不分块**——编码只用一次，非必要不开 tiled encode；
3. **overlap 取 16 像素**——太小有网格接缝，太大分块收益缩水；
4. **3D tile 时间窗口不要切太碎**——否则破坏 VAE 时序隐空间连续性，运动断层。

**安全阀纪律**：tiled decode 默认给开关，显存充足时可关闭直接整图解码，避免接缝与轻微融合模糊。

## 7.6 两套兜底预案（基底材料）

1. **4.5B 混合量化后 16G 仍紧 / 长帧易爆**：主干降到 4B，混合量化后权重再省近 1GB，余量宽裕；代价是上限小幅下降。
2. **量化后出现明显 flicker / 画质或风格崩坏**：不要硬拉全量化，改为主干 fp16，只做 KV cache int8 + 专家 int8，牺牲显存换稳定性（不突破 §7.2 红线）。

## 7.7 台账纪律（继承 v1.2 §7.1）

唯一可信台账 = 内存快照（torch.cuda.memory_snapshot），v1.0 全部手算数字作废。【红线】§7.4 的 12~14GB 为基底材料估算，须以实测快照回填后方可作为发布口径。

## 7.8 采样器

ODE 流匹配采样器 + 可选 coarse-to-fine 调度（基底材料）；步数口径按 §2.5 新底座校准，不继承 v1.2 的 3 步硬约束。

# 第 14 章 风险、边界与坦诚声明

## 14.1 继承 v1.2 八条风险

底座核验/FP8 硬件/引用可信度/台账风险等全部继承，其中「底座核验风险」已随底座更换关闭。

## 14.2 v2.0 新增风险

1. **训练线资源风险**：换底座后训练成为必需，20GB 单卡与渲染串行，8 层挂载 MVP 起步（继承 v1.2 §24.3 资源现实）；训练不足则 V1 基线无法验证，全链路阻塞。
2. **量化敏感性风险**：时序/skip/AdaLN/输出头是画质底线，16G 余量本就紧，一旦为省显存突破 §7.2 红线， flicker 与画质崩坏会直接打击项目最在意的两项指标；预案见 §7.6。
3. **工程推断未验证风险**：α 初值、时序辅助头残差、跨尺度 loss、噪识门控四项均【工程推断】，不得当结论引用，必须消融（§12）。
4. **与教师不同构风险**：§3.8 已论证学生在条件通路与注意力结构上与参考架构（Wan 2.1/2.2，仅架构参考非教师）更不同；蒸馏对齐完全依赖层特征对齐 loss（§3.7）的效力，若该 loss 不足以弥合双轴混血教师（M85 + 时序低通）与学生 Udit 4.5B DiT 的差异，需回退考虑部分架构向教师靠拢（如增强瓶颈层 Full 3D Attention、引入时序低通算子）。
5. **显存数字未实测风险**：§7.4 的 12~14GB 为基底材料估算，快照回填前不得作发布口径。

## 14.3 坦诚边界

- v2.0 是一份**架构重构蓝图**，V1 尚无任何实测；早期底座上的实测数据不构成 v2.0 的有效性证据，仅作方法论参考；
- 「16G 跑通」是可行性判断（基底材料结论），不是已验证结果；
- Wan 2.1/2.2 仅作**架构参考**（RoPE/注意力范式），架构细节来自技术报告解读而非逐行核对开源代码；**已不是蒸馏教师**（V2-21 起教师定案为双轴混血，见下）。
- **代码进度与实证边界（V2-17，V2-20 更新）**：本版已落地的 5 个纯 CPU 模块（`quant_plan` / `distill_loss` / `ablation_matrix` / `engineering_hygiene` / 自检校准）证明的是「结构可前向、红线可判定、loss 可反传、清单可执行」，**不是**「画质/时序/显存达标」。4.5B 参数量用 meta device 精确计数为 4.536B（已坐实）；**V2-19 GPU 真机已跑通 4.536B bf16 真前向（权重 9.076GB / 峰值 9.21~11.91GB / 剩余 ≥9GB）、Triton kernel、SDPA FLASH（3.45×加速）、时序节点直测；V2-20 已装社区 Triton 后端真 FA2（`flash2` 自动走 `fa2_package`，5 组数值对齐全 PASS）**——但真蒸馏训练、真 int8 量化、GSA vs 2+1D 真对照、VAE compile / 流优先级仍未验证，不冒充通过。画质/时序质量达标仍需成片主观+客观评测，前向跑通 ≠ 画质达标。**蒸馏教师硬约束（V2-21 定案）**：XT-5B 只作出参考片工具，不作教师；Wan 2.1/2.2 仅作架构参考、不作蒸馏教师；**唯一教师 = 双轴混血（M85 权重 + 时序低通算子），flicker 0.0244 / 身份 0.9892，20 步，学生跟 20 步训练**。按项目定案原样记录教师名称与指标，不展开 M85 来源与低通实现细节。本轮只训主干，三专家冻结。

## 18. 3.5B 主干改造落地（V2-26，2026-11-22）

> 本节记录从 4.537B 基线到 3.5B 定案主杆的**已落地代码改造**（非蓝图）。改动文件：
> `uvit3d.py`（858→1243 行）、`vlm_bridge.py`、`train_backbone.py`、`run_training_daemon.py`、
> `selftest_uvit3d.py`。自检 **87→98 项全 PASS**（纯 CPU）。**仍未做**：教师热启动、
> CFG-A 预编码、真训练（见 §14.3 边界）。

### 18.1 参数账（meta device 实测）

| 项 | 参数量 | 说明 |
|---|---|---|
| 基线（旧） | 4.537B | 贵版 adaLN 每块 `Linear(3072,18432)=56.6M` ×26 = 1.47B（占 32.5%、算力仅 0.048%）|
| 教师式 adaLN | **省 1.453B** | 共享两层 embedder(19M) + 每块 `(1,6,3072)` 小表(0.55M)；教师表同构可热启动直拷 |
| bottleneck 2→6 | **+0.453B** | 全局 3D 联合注意力容量 ×3，算力 1.16× |
| head AdaLN(R7) + cond_dim 4096 + 共享 embedder | +29M | UMT5-XXL hidden 前置、画质小赚 |
| 新增轻量算子 | +1.61M | 时序低通 / 运动头 / 频域分支 / 局部卷积 / SNR / 参考对齐 |
| **合计** | **3.569B** | 独立核算口径 3.518B（未计上述 +51M 新增件），两个数都对 |

逐项分账：FFN 2264.9M(63.5%)、attn 1132.5M(31.7%)、embed/head 37.4M、adaLN embedder 18.9M、逐块表 0.55M、新算子 1.61M。权重+梯度显存从 18.15GB → 约 14.3GB。

### 18.2 RoPE B1 根治（踩坑记录）

complex128 buffer 被 `Module.to(bf16)` 静默丢虚部（B1），改造为实数 fp32 cos/sin 表（模型级 lru_cache 共享、去 per-batch loop、bf16 快速路径）。**关键纠错**：初版用 `cat([cos,cos])` + half-split `rotate_half`，与教师复数版 `view_as_complex` 的相邻配对不等价——真网格 (3,15,22) 实测差 **6.89**。修正为 `[L,c]` 复数通道级表 + 相邻配对 `[-x_odd,x_even]` + `repeat_interleave(2)`，数值对齐复数版、保范数。复数版函数保留供 selftest 逐值对照。

### 18.3 新增模块（定案全上）

- **r512×12 VLM 注入链**：北大桥 88M（冻结、gen_model.pth 加载，当前文件未到位→随机顶上）+ 12 个低秩 CrossAttnInjector（r=512，每层 12.6M，全秩 37.75M）。`use_vlm=True` 才实例化，逐 token 文本注入补 R3 容量差距。
- **时序低通 conv**（9K）：depthwise temporal conv，教师 flicker 0.0244 的关键算子，残差修正起步。
- **运动估计头**（1.6M）：帧级 `[B,T,3]` 运动向量，训练辅助监督、推理可摘。
- **频域分支**（1.6M）：FFT 幅度谱 → 小 MLP → 零门控全局频率调制，抗彩噪/伪影。
- **局部卷积**（28K）：depthwise spatial conv 3×3，补 Transformer 缺失的局部归纳偏置。
- **SNR 分层条件编码**：流匹配噪声级天然是 sigma，小 MLP 出逐块 gate 调条件粒度，无额外标注。
- **参考帧残差对齐旁路**：参考 latent 与当前 latent 特征对齐输出偏移调制；`ref=None` 时整路恒等、不进计算图，不阻断无参考训练。
- **AdaLN 双分支调制**（轻量叠选，取代 MoE 高阶路由头）：独立 scale/shift 小 MLP 解耦均值/方差控制，默认关、保留接口兜底。

### 18.4 训练层安全加固

存档串行化（起新线程前 join 上一线程，最坏 9GB 而非 27GB RAM——多线程同时驻留大 state_dict 的内存尖峰风险）、`save_every` 100→500、`cycle_steps` 300→1000、`steps` 9000→3000、F2 谱初始化 `normal(0,0.02)`（教师实测谱 0.02 vs torch 默认 0.0104 差 2×）、F5 预热 100 步冻结 spectral_norm 幂迭代（消检查点重算不确定性 + compile 断图点）。

### 18.5 已知边界

- latent 仅 `latent/src` 两字段、**无 text_emb**——无教师分支时文本条件是随机向量、无语义；真语义需教师预编码补上。
- 北大桥权重 `gen_model.pth` 未在盘上找到——桥当前随机初始化，拿到文件后按 `expected_shapes()` 严格加载。
- 教师热启动 + CFG-A 合成场（`v=uncond+6(cond-uncond)`）预编码脚本尚未实现。
- 16s/步基线是旧代码口径；评审将跑 50 步 profile 验证 L0 包（rope 实数化/合并 GEMM/F.rms_norm）的真实提速。

## 19. MoE 形态对齐：全局条件空间专家（V2-27，2026-11-22）

**V2-24 的按块 FFN 替件版 MoE 已废弃。** 该形态在 26 个 block 内各建 3 专家吃 token 流（5.89B）+ 空闲 ffn（1.96B），与架构定版差 26 倍，已按 speedrun 定版重写。

### 19.1 定版形态（全模型一套）

- **类**：`GlobalConditionalMoE`，在 UViT3D 主层实例化**一次**（`self.global_moe`），不在 block 内。
- **输入/输出**：吃共享条件 `e [B,3072]`（不是 990 token），输出同维 `c_expert [B,3072]` → 算力开销 ≈ 0。
- **专家**：3 个独立 4 层 MLP（hidden=13440），**单专家 330.37M**；合计 **0.991B（≈1B 锁死）**。
- **路由**：Top1 argmax（straight-through 梯度，router 可训）；风格信号可由 VLM 风格头 `style_logits` 下发，缺省走内部 router。
- **注入**：α 门控加法注入条件 e，范围 **blocks 7–12（6 块）**——加法，不替换 FFN。
- **回退红线**：α 零初始化 → `c_expert ≡ 0` → 主干逐 bit 恒等；专家输出经 tanh 有界，杜绝 `0×inf=NaN`。

### 19.2 参数账与阶段划分

| 形态 | 主干 | MoE | 合计 | 备注 |
|---|---|---|---|---|
| 阶段1（use_moe=False） | 3.569B | 0（不实例化） | **3.569B** | 当前训练配置 |
| 阶段2（use_moe=True） | 3.569B | 0.991B | **4.560B** | +1B 全局专家 |

## 20. 条件编码器 + 专项 Block + 细节头：补到 4.0B（V2-28/29/30，2026-11-22）

经三轮评审迭代加模块，主干从 3.569B 精确补到 **4.000B**（meta device 实测 3,999,944,893）。全部零门控起步（初始严格恒等，不扰动已训主干），纯 torch SDPA，不写自定义 corr kernel（避开 RDNA3 烂 kernel / 碎片化）。

### V2-28 两个轻量化条件编码器（`model/cond_encoders.py`，沿用 VLM 注入链的「减层 + 低秩」方案）
| 模块 | 配置 | 参数 | 作用 / 接入 |
|---|---|---|---|
| `HierarchicalStyleEncoder` 分层风格条件编码器 | 6 层 r384 低秩 + 分层可学习加权 | **72.04M** | 风格 token → 风格条件（加法入 AdaLN）+ 路由 logits（复用全局 MoE 的 `style_logits` 接口）；约束 MoE 画风分区、减串味 |
| `ReferenceResampleAlignEncoder` 参考帧重采样对齐编码器 | 6 层 r384 cross-attn + 可学习 resample query | **68.55M** | 参考帧 latent 与生成 token 做特征对齐，角色保形（抗变脸/漂移）；替换原 `ref_proj` 旁路，`ref_latent=None` 恒等 |

合计 **140.6M**。`forward` 新增可选参数 `style_tokens`；不传时整条路不进图，与无编码器配置逐 bit 恒等（自检 §12 验证）。

### V2-29 两个专项注意力 Block（`SpecializedBlock`，uvit3d.py）
| 模块 | 注意力域 | 参数 | 插入位置 / 作用 |
|---|---|---|---|
| 纯时序 Block | 只时间注意力 | **113.27M** | encoder 之后（主干中段），专治频闪 / 角色抖动 / 动作跳变 |
| 纯空间 Block | 只空间注意力 | **113.27M** | decoder 之后（深层），专磨单帧五官 / 线条，不增加时序计算 |

### V2-30 DDT 高频细节残差头（`DetailRefineHead`，uvit3d.py）
- per-token MLP `dim(3072) → 19456 → out(192)` = **63.53M**，加在主速度场头输出上。
- 设计依据：Motif-Video 2B（2026）DDT 解耦解码——低频语义与高频细节分离解码，VBench 83.76 超过 Wan2.1-14B；本头专补高频（五官/线条/纹理）。
- 零门控起步，per-token 算力约 0.06 TFLOP（<1% 步时），不进主干 30 块。

### 参数轨迹与门禁
`3.569B → +140.6M = 3.710B → +226.5M = 3.936B → +63.5M = 3.9999B ≈ 4.0B`。
自检 §9 硬断言同步为 **3.99~4.01B**；新增 §12/§13/§14 三段测试（形状 / 零门控严格恒等 / 梯度 / 逐 bit 接口兼容），全套 **130 项 PASS**。

> 选型说明：社区 SANA Linear DiT / MoDDiT token routing / S²DiT SSA 均为「省参数/省算力」路线，不能用于补参数；DDT 细节分离是 2026 验证的「补质量」路线，故选 V2-30 作为补到 4B 的收尾模块。FFN 已确认为设计选定的 Dual-Act 分段 SwiGLU（非标准 SwiGLU）。

## 21. 检查点覆盖补全：三处漏网激活回收（V2-31，2026-11-22）

显存勘察（meta device + forward hook，真实 shape B=1/N=990/dim=3072/bf16）发现：30 个主块都走 `_blk_call` 的 checkpoint 包装，但 V2-29/V2-30 新增的两个专项 Block 与 DDT 细节头是**直接调用**，激活全程驻留：

| 漏网模块 | 实测驻留激活 | 大头 |
|---|---|---|
| 纯时序专项 Block | 87.2 MB | FFN w12 32.4M + qkv 18.2M |
| 纯空间专项 Block | 87.2 MB | 同上 |
| DDT 高频细节头 | 45.0 MB | up 投影 38.5M |
| **合计** | **219.4 MB ≈ 0.22 GB** | |

**改动（不减参数、不减功能、数值不变）**：
- 两个专项块的调用改走 `self._blk_call(...)`（签名本就兼容 `(z, cond, grid)`）；
- `OutputHead` 新增 `detail_ckpt` 开关，`UViT3D.enable/disable_gradient_checkpointing()` 同步切换；构造时按 `cfg.grad_checkpoint` 初始化，训练侧默认开（`--no-ckpt` 才关）；
- `ckpt_scope="block"` 下三模块均被 checkpoint 重算，`"ffn_only"` 下与既有策略一致（只重算 FFN 子层）。

**验收**：自检 §15 新增 9 项（checkpoint 前向逐值等价、反向确实重算 forward 2 次、输入梯度等价、开关同步、集成路径验证），全套 **139 项全 PASS**；参数量仍为 **3,999,944,893（4.000B）**不变。

> 未采纳项：①「零门控短路」——gate=0 时跳过计算虽省得更多，但 gate 永远收不到梯度、学不开，需额外 warmup 兜底，风险大于收益；②「FP8 / compile」——RDNA3 无 FP8 矩阵核且违反不降精度，compile 本机实测慢 2.4~5.6×。16GB 固定占用（权重 8 + 梯度 8）是 bf16 全参硬底，不动精度无法再降。

# 结语

v2.0 = v1.2 的工程骨架与实测资产 + 一次彻底的底座换血。

v1.2 用 E4~E9 把「零训练外挂」这条路的天花板测了出来：能做的都做了，注入通路打通了，但身份保形、时序门控、多参考全都指向同一个结论——**底座不换，上限就在那里**。底座更换是这些实测数据的直接结论。

v2.0 接过的不是一个更稳的方案，而是一个更高的上限，以及与之匹配的训练成本和工程风险。4.5B U-ViT 的每一处改动——AdaLN、加权 skip、2+1D、SwiGLU、通用增强专家——都对准 v1.2 撞过的墙，服务于全方位更高更快更强的目标。16G 混合量化的每一条红线，都守着画质与时序这两项最在意的指标。

诚实地说：这份蓝图尚未实测。但它是站在 v1.2 全部实测数据的肩膀上写的，知道自己要去哪里，也知道自己哪里还没验证。

**没有一个分支被砍掉，只有还没轮到的分支——以及现在终于轮到的底座。**
